## 3. 根因

### RC-1（真缺陷，已修）`_scope_text` 空格拼接制造假相邻

`agent/plan_windows.py` 的 `_scope_text` 把标题 + pending_note + 各交付条目用**空格**拼成一串，`scope_windows` 拿整串喂 `_wants_create_level`。`_LEVEL_CREATE_RE` 的动词与名词之间允许 `\s*`，于是「…（C++ 类或蓝图）的**创建**」与下一条「**关卡**内可拾取的手榴弹道具放置」在拼接缝上被读成「创建关卡」。`_wants_create_level` 的 docstring 明说「中间夹了别的词不算」，但拼接缝让两个**各自独立的话**变成了假相邻。

后果链：范围 C 补出一扇缺槽位的 `create_level`（W3）→ W3 人工跳过 → C 交付整段没跑，集成 note 里多出「C（窗口没跑完：W3）」这种把假窗当进度的噪音。

### RC-2（真能力缺口，不是缺陷）手榴弹链路无可执行窗口

`unresolved` 原文：`没有对应的动作，因此无法创建或编辑手榴弹蓝图或爆炸效果；place_actor 也缺少唯一的蓝图名，level3 未给出唯一关卡路径`。CATALOG 里确实没有创建 C++ 类、改蓝图图、做特效、加输入映射的动作；`implement_shooter` 这类复合脚本也没有手榴弹对应物。B（FPS 玩法补齐）由台账 pending 注入且同样零窗口，C 依赖 B、D 依赖 B/C —— B/D 缺口是诚实判定，人审已确认，`no_evidence` 收口符合 20261024 的整改口径。

### RC-3（口径核对，不是缺陷）「level3」不给槽位是对的

原句的「level3」不是 `L_` 名，pending_note 已声明「level3 / L_NewTest3 尚未唯一确认，确认前不改场景」。`create_level` 缺槽位按设计暂停、不猜 —— 即使 RC-1 修掉，这条也不该变成可执行窗。
