# 20261118-164628 W2「改控件图」失败 · 根因分析

- run：`data/runs/20261118/20261118-164628.md` · 状态「部分完成」/ 停因 `retry_exceeded`
- 原句：`打开编辑器，给UI左下角血条左边隔10像素，添加一个头像框，里面可以配置图片。参考资产：/Game/UI/WBP_FpsHUD`
- 结论时间：2026-11-18

## 1. 一句话结论

**插件有改控件的完整能力，不是「Monolith 不具备该能力」。** 模型其实已经产出了一份**合法**的
UMG Spec（SizeBox/Border/Overlay/Image 头像框），但被 `agent/umg_spec.validate_spec` 用
**snake_case 锚点白名单**判成 `unknown_anchor`（模型按 UE 枚举写 `BottomLeft` / `Fill`），
`produce` 因此返回 `None`，`_maybe_attach_umg_spec` 没挂上 Spec，`repair_blueprint` 于是落到
**旧的 discover 猜 action** 路径；`ui` 命名空间里 `compile` 针名同时命中 `compile_widget` 与
`dump_blueprint_compile_log`，判不出唯一 action ⇒ 连试 3 次、`exec_count=0`，最后被写成
「Monolith 不具备该能力」。此外内核还有两个真机才暴露的缺口：node 级原语没带 `asset_path`、
`bIsVariable` 走了 `set_widget_property`（不在 allowlist）。

## 3. 根因

1. **RC-1（主因·判词过严）** `umg_spec.validate_spec` 用固定 snake_case 白名单硬判锚点。模型按 UE
   枚举/口语写 `BottomLeft/TopCenter/Fill` 是**合法且自然**的，却被整份否决 ⇒ `produce=None` ⇒
   掉进 discover。这与「代码缺口」无关，是**判词把模型正确答案否掉**。
2. **RC-2（假失败话术）** `edit_widget_blueprint` 在 monolith 下没有唯一 action，`repair_blueprint`
   却仍用 `needle="compile"` 去 discover 猜；猜不中把「缺 Spec」误写成「Monolith 不具备该能力」。
3. **RC-3（内核真机缺口，离线假 call 掩盖）** node 级原语无 `asset_path`；`bIsVariable` 走错
   `set_widget_property`；画刷形状未归一；`list_widget_properties` 返回分类属性表（list）而非扁平
   `{名:值}`，按属性值硬判会假失败。

## 4. 修复

`agent/umg_spec.py`
- 锚点**别名归一**：新增 `normalize_anchor()`，`BottomLeft→bottom_left`、`Fill/full_screen→stretch_fill`
  等；`ANCHORS` 对齐 `set_anchor_preset` 真机 preset（含 `stretch_*`）。`validate_spec` 用归一键，
  不再整份否决。
- **变量暴露**：新增原语 `set_variable` → `ui.set_widget_is_variable`；节点 `is_variable:true`
  或 `properties.bIsVariable` 摘出来走它（不再进 `set_widget_property`）。复核读回
  `get_widget_tree.is_variable` 做断言。
- **画刷归一**：`corner_radius` 数字→对象、`tint_color` 列表→`"r,g,b,a"`。
- **表现层 best-effort**：锚点/槽位/属性/画刷失败只记 `warning` 不阻断（硬合同=控件在+类对+变量+编译）。
- **补 `target`**：`plan_ops` 每个 op 都带控件蓝图 ref，修掉 AddWidget `asset_path` 为空。
- **成功补判词**：`build()` 成功时补 `build`/`test`（kind=`blueprint_compile`），让
  `c-blueprint_compile` 条款能翻；`c-widget_graph` 由 `run_windows._absorb_result` 合成。
- `SPEC_HINT` 提示模型用 snake_case 锚点、`is_variable` 暴露图片、画刷形状。

`agent/sequence.py`
- `edit_widget_blueprint` 在既非 FPS HUD 又无 Spec 时**不再盲试 discover**，直接诚实失败并点名
  「缺 UMG Spec，不是 Monolith 没有能力」，不再出现 3 次误导话术。

`agent/spec_pipeline.py` / `agent/spec_toolmap.py`
- `run_ops`/`build_domain` 透传 `warnings`；toolmap 登记 `umg.set_variable → ui.set_widget_is_variable`。

## 6. 残余（诚实边界）

- 位置/槽位是 best-effort：非 CanvasPanel 子槽位（SizeBox/Border/Overlay）不接受锚点/position/size，
  这些写会带 `warning` 跳过；硬合同只要「控件在 + 类对 + 变量 + 编译」。「离血条左边 10px」的像素级
  摆放不进入机器判据（与既有 widget_graph 判词口径一致）。
- `bIsVariable` 之外的「图片源做成设计器可配置参数（纹理参数绑定）」仍需更多原语，本次只做变量暴露。
